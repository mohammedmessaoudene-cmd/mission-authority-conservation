# 03. Découverte et versions

**Verdict : PROFILER** · Analyse documentaire du 1 novembre 2026.

## Besoin et cas concret

Un client découvre un outil, conserve sa description puis appelle un service dont le contrat a changé. Une extension indispensable peut aussi être ignorée sans signal visible.

## Leçon des protocoles Internet

Comme une représentation HTTP en cache, une annonce de capacité a une fraîcheur et une identité ; elle n'est pas une autorisation.

## Meilleure composition existante

Agent Cards A2A, mécanismes de négociation MCP et règles HTTP de cache fournissent déjà découverte, versions et revalidation. Leur composition dépend des endpoints et des extensions réellement supportés.

## Opportunité résiduelle à éprouver

Rendre explicite la relation entre description utilisée, version demandée et contrat exécuté. Une empreinte de description peut aider sans prouver le comportement interne du service.

## Plus petit livrable utile

Un profil narratif de compatibilité précisant cache, changements incompatibles et refus des exigences essentielles non reconnues.

## Contre-exemple décisif

Une carte inchangée annonce un schéma mais le serveur applique une autre interprétation : une signature de carte ne suffit pas.

## Plan de validation — NON EXÉCUTÉ

NON_EXECUTE : confronter annonce périmée, extension obligatoire absente et témoin compatible au meilleur mapping existant ; observer refus explicite ou conservation de la même interprétation.

## Décision GO / NO-GO

GO si une divergence interopérable reste sans règle ; NO-GO si la négociation et la revalidation existantes la traitent déjà.

## Agents actuels

Les annonces et mécanismes de cache sont documentés, leurs usages restent variables.

## Autonomie accrue — hypothèse conditionnelle

Des mises à jour fréquentes accroîtraient les risques de décalage contractuel.

## AGI/ASI — recherche conditionnelle

Une AGI hypothétique ne doit pas deviner une extension normative manquante.

## Limites

Cache frais ne signifie pas politique fraîche. Aucune preuve de code effectivement exécuté ni bénéfice intégrateur mesuré.

## Sources primaires et statut établi

- [A2A 1.0 — Agent Cards, extensions et versionnement](https://a2a-protocol.org/v1.0.0/specification/) — Spécification officielle versionnée 1.0 ; portée limitée aux clauses consultées.
- [HTTP Caching — RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html) — Internet Standard, STD 98, juin 2022.
- [MCP — versionnement](https://modelcontextprotocol.io/specification/versioning) — Documentation officielle indiquant 2026-07-28 ; négociation distincte des versions antérieures.
